# KRTaker Landing Site — Improvement Plan

Status of the site today:
- 21 static pages, generated by `build/landing/build.py` (template + page content files)
- Shared design system in `web/css` + `web/js`, served via `docs/landing/` behind a trycloudflare tunnel
- Register form saves to localStorage only — no backend, no email, no trial logic
- DiziConCard-inspired layout; KRTaker brand in REM blue

---

## Phase A — Quick wins (polish & trust, 1 session)

| # | Task | Why |
|---|------|-----|
| A1 | Replace hand-drawn hero mockup with real screenshot of the v2.2 prototype (dashboard + tenant view) | Instant credibility — "what you see is what you get" |
| A2 | Animated hero (fade/slide on load) + scroll-reveal for sections | Feels premium, keeps visitors engaged |
| A3 | Bengali font support (Hind Siliguri) + বাংলা language toggle on key pages | BD market expectation; owners/tenants read Bengali |
| A4 | Trust strip: bKash / Nagad / SSLCommerz / DCCI / BIDA badges | BD buyers need payment + institutional trust signals |
| A5 | Dark mode toggle (CSS variables already exist — mostly wiring) | Modern SaaS expectation |
| A6 | Mobile sticky "Start free trial" CTA + bottom action bar | Mobile is the primary BD browsing surface |
| A7 | Contact / partner-application form → POST to a real inbox (or email alert) | Currently a dead-end toast; loses leads |
| A8 | a11y pass: focus states, aria labels, alt text, contrast | Quality bar + SEO side-benefit |

**Exit check:** Lighthouse ≥ 90 on Performance/SEO/A11y for home + pricing.

## Phase B — Conversion funnel (the register page)

| # | Task | Why |
|---|------|-----|
| B1 | Multi-step register wizard: Plan → Role → Account → Confirm (progress bar) | Higher completion than one long form |
| B2 | BD mobile number OTP (SMS gateway) OR email verification — pick SMS-first | BD users trust OTP; blocks fake signups |
| B3 | Wire signup to Phase 2 backend (`/api/auth/register` + `subscribers` table, trial end = now+14d) | Turns demo into a real tenant acquisition pipeline |
| B4 | Google login as alternative (works for NRB/partner segment) | Friction reduction |
| B5 | Post-signup: welcome email + calendar link for onboarding call | 14-day trial needs activation |
| B6 | Waitlist fallback: if backend isn't ready, capture name/phone to a spreadsheet/DB with "notify me" | Don't lose leads while B3 is in progress |

**Exit check:** signup lands in a queryable table + triggers email; 0 dead-end submits.

## Phase D — Technical & SEO foundation

| # | Task | Why |
|---|------|-----|
| D1 | Real domain (suggest krtaker.com) + certbot HTTPS — reuse REM nginx recipe | trycloudflare URL is temporary; kills trust for a paid product |
| D2 | Static hosting or production tunnel: Cloudflare Pages / Vercel / nginx on this box | The tunnel link changes every restart |
| D3 | sitemap.xml + robots.txt + canonical URLs + JSON-LD (Organization, SoftwareApplication, FAQPage) | Discoverability; FAQ schema alone lifts SERP presence |
| D4 | OG/Twitter card images per page (1200×630) | Link shares look professional on Telegram/WhatsApp/FB |
| D5 | Google Search Console + Bing Webmaster verification | Measure organic demand |
| D6 | Perf: inline critical CSS, preload font, lazy-load below-fold images | Mobile speed in BD (slower networks) |

**Exit check:** site reachable on real domain over HTTPS; Lighthouse ≥ 90; Search Console reporting clicks.
